## Schéma d'un dispatch

| Champ | Sens |
|---|---|
| `ID` | `D-N###`, immuable |
| `MISSION` | Ce qui doit être exécuté |
| `SOURCE` | Bill (découverte typée) / Clara (design borné) / Capitaine (décision vision) / Heartbeat (anomalie routée) |
| `EXÉCUTANT` | Qui exécute (agent, session, holon) |

| `STATUT` | Un seul à la fois (voir cycle) |
| `PREUVE` | PR, SHA, reçu R10, lien |

| `MAJ` | Dernière transition (date EDT) |

## Cycle de statuts

`À TYPER` → `EN DESIGN` → `PRÊT` → `ASSIGNÉ` → `EN COURS` → `PR OUVERTE` → `ROUTÉ MERGE` → `MERGÉ`
Branchements : `BLOQUÉ` (depuis n'importe quel statut, avec raison) → reprise au statut d'origine une fois débloqué. `REJETÉ` (décision Doctor, motif obligatoire).

Interdit : un dispatch sans statut ; un statut « actif » sans reçu R10 (mission_id + SHA) ; un swarm sans design Clara signé.

**Gate TERMINÉ — PRs Jules (M-07 P2)** : un dispatch impliquant des PRs Jules ne passe à TERMINÉ que si chaque PR est « Ready for review » **avec** `Fixes #N` (zéro session >24h sans reprise).
